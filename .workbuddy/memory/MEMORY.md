# 项目长期记忆

## 用户明确的评价标准（2026-11-08 12:02 · 最高优先级）

> **原话：「竞赛和网页大作业这边只要你做的足够好看就行，没人关心你的技术栈」**

- 课程大作业 / 比赛竞赛这两个场景，**唯一在意的是视觉冲击力**。技术栈、工程规范、文档、探针、git、性能数字、TypeScript、后端、CI 都**不计入评价**。
- 因此此前围绕 B+C（产品化 + 工程打磨）的规划、以及 1800 行文档 / 7 个探针 / git 基线 / SVG 降采样 / 键盘可访问性等工程投入，**对这两个场景的分数基本无效**，属于自我感动，不要再拿来当卖点。
- 按此标准重排：此前给出的评分表（技术深度 9.0、工程规范 9.5 等）权重不成立；判断一个改动值不值得做，只问「**这会不会更好看**」。
- 资源应集中在评委 / 老师真正会看的 **2–3 页**（首页 + 一个 3D 页 + 一个专题页），不要 18 页平均用力。
- 只有当目标被明确改成「真做产品」时，才重启 B+C 与阶段 0 的后端决策。

## 协作约定

- 「不确定的就问我」：**设计取舍必须问，技术性 bug 直接修**，别拿实现细节打扰用户。
- 用户会让别的 AI 接手后续修改，关键判断必须写进交接文档（`NEXT_PHASE.md` 等），不能只留在对话里。
- 用户对视觉细节敏感：曾一次性指出 9 处配色 / 图版 / 布局问题并要求「举一反三」全改。反馈截图时先分辨「入场动画中间态」与「真实配色错误」。
- 用户不喜欢空泛罗列技术点；给建议要收敛到「最该改的那一件事」。

## 视觉偏好（2026-11-08 12:30 定稿）

- **否掉**：「三条独立走向的波浪硬色带」——走向与等高线不一致、硬边界、铺满下半幅、显脏，像廉价背景板。用户原话「这个加了色块反而更丑了，可以加，但不能这样加」。
- **选中**：「纯光影」——金圆柔光晕 + 底部暗角 + 每 5 条里的主线提亮加粗，**完全不加色块**。已落到 `scripts/generate_art.py` 的 `art_hero()`。
- 备选未选但未被否：「同构渐层」（同一条波形的极淡单色渐层，无硬边界），以后别处要加层次可用。
- **通用原则**：不要另起一套形状语言盖住已有图形；加东西要和原有线条同频、透明、克制，保住墨底通透感、细线仍是主角。
- 首页大标题金色已改为 `#A9701F`，**仅一处**；用户尚未对「是否全站铺开」表态，别擅自扩大。
